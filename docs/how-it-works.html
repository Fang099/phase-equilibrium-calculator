The pipeline

The program is a chain of Python modules. Each one takes the output of the one before, so each can be tested alone. The calculator page and the command line both feed the same chain.

  1. Input checkerinput_checker.py

    Reads a plain-text description of the mixture, converts units, fills in database values, and decides whether the information is sufficient and which calculation it implies.

  2. Thermodynamic modelsthermo_models.py

    Builds one object per phase. Each object answers one question: what is the fugacity of every compound at this \(T\), \(P\) and composition?

  3. Equilibrium solverequilibrium_solver.py

    Finds the states where fugacities match between phases, and sweeps them into diagrams and tables.

  4. Outputplotter.py · web_api.py

    Draws figures with Matplotlib from the command line, or returns numbers as JSON for the charts on the calculator page.

Supporting files: compound_db.py and data/compounds.json (the property database), and numerics.py (the root finders).

2. The input checker

        
check_input(text) works through the file in five steps.

        
    
          
  1. Parse. Each line is a quantity, an optional target (a compound or a pair) and a value with a unit. Unknown names get a spelling suggestion.
    2. 
          
  2. Convert units to SI: kelvin, pascal, joule per mole, kilogram per mole.
    3. 
          
  3. Fill from the database. With database = builtin, any property the file does not give is looked up: \(T_c\), \(P_c\), \(\omega\), molar mass, Antoine constants, and the pair's NRTL parameters, van Laar parameters or Peng–Robinson \(k_{12}\). Values written in the file always win.
    4. 
          
  4. Choose a route for each possible equilibrium. If an equation of state was requested and its constants are complete, it is used for both phases. Otherwise the checker looks for a vapor-pressure source for each compound and uses the activity model for the liquid.
    5. 
          
  5. Count degrees of freedom and compare with what was specified.
    6.

3. The fugacity models

        
build_system(text) creates two objects for this request: a liquid and a vapor. Every phase object has the same method, ln_f(T, P, x), which returns \(\ln \hat f_i\) for each compound. The solver never needs to know which model is behind it.

Activity route (this example)

        
The liquid fugacity is the table's first row, one line of code:


        
The pure-liquid fugacity \(f_i^{L}\) is the vapor pressure from the Antoine equation, times the Poynting correction \(\exp[V_i^{L}(P - P_i^{\mathrm{sat}})/RT]\) when a liquid volume is given. It is computed in logarithms so that very low vapor pressures do not underflow:


        
The vapor on this route is an ideal gas, \(\hat f_i = y_i P\). A compound marked non-volatile gets \(\ln \hat f_i = -\infty\), so it never enters the vapor:


        
\(\ln\gamma_i\) comes from the activity model. The van Laar class reads its two parameters at the temperature asked for (a number, or a TFunction as above), checks that they have the same sign, and evaluates the two formulas from the Concepts page:




        
NRTL is written for any number of compounds with matrices. _tg gives \(\tau_{ij} = \Delta g_{ij}/RT\) and \(G_{ij} = \exp(-\alpha_{ij}\tau_{ij})\); ln_gamma is the general NRTL expression, with the two sums built by matrix products:



        
Each model also has ge_rt, \(G^{E}/RT\). The tests differentiate \(nG^{E}/RT\) numerically and check that it reproduces ln_gamma, so the two cannot disagree.


        
Equation-of-state route

        
CubicEOS stores van der Waals and Peng–Robinson as one residual Helmholtz energy with two constants:

        \[ \frac{A^{\mathrm{res}}}{NRT} = -\ln\!\left(1-\frac{b}{v}\right) - \frac{a}{bRT(\delta_1-\delta_2)}\,\ln\frac{v+\delta_1 b}{v+\delta_2 b} . \]
        
This is the fundamental equation the project starts from, in code. With mixture totals \(D = n^2 a_{\mathrm{mix}}\) and \(B = n\,b_{\mathrm{mix}}\):


        
Everything else is a derivative of this function. Pressure is \(P = -(\partial A/\partial V)_{T,n}\), and the fugacity coefficient is \(\ln\hat\varphi_i = \partial(A^{\mathrm{res}}/RT)/\partial n_i - \ln Z\), written out analytically:


        
To work at a given \(T\) and \(P\), the cubic in \(Z\) is solved in closed form, and the smallest root is taken for a liquid, the largest for a vapor:


        
The tests compare the pressure and \(\ln\hat\varphi_i\) with numerical derivatives of helmholtz_res.

      


      
      

        
4. The equilibrium solver

        
K-values and the material balance

        
Equal fugacities, \(x_i\hat\varphi_i^{L} = y_i\hat\varphi_i^{V}\), give the K-values directly. For the activity route the liquid's "fugacity coefficient" is \(\gamma_i f_i^{L}/P\), so this is modified Raoult's law:


        
For a feed \(\mathbf z\) of which a fraction \(\beta\) is vapor, the material balance is the Rachford–Rice equation. With \(\beta = 0\) it is a bubble point and with \(\beta = 1\) a dew point:

        \[ \sum_i \frac{z_i\,(K_i-1)}{1+\beta\,(K_i-1)} = 0 . \]


        
One bubble point

        
At a trial temperature, the K-values depend on the vapor composition, and the vapor composition on the K-values. _sat_eval iterates the two until they stop changing (successive substitution), then returns the Rachford–Rice residual:


        
saturation() then treats that residual as a function of the one unknown, temperature for a Txy diagram or \(\ln P\) for a Pxy diagram. It steps out from a guess until the residual changes sign, then closes in with Brent's method:


        
The guess comes from K-values that ignore composition (Wilson's correlation for an equation of state, the ideal-solution value otherwise). For an equation of state, a result where liquid and vapor came out identical is rejected as the "trivial solution" near a critical point.


        
The diagram and the azeotrope

        
vle_diagram() repeats the bubble point across the composition range, each point starting from the previous answer. Each bubble point also gives one point of the dew curve, since the vapor it finds is at its dew point:


        
An azeotrope is where \(y_1 - x_1\) changes sign between two neighboring points. The exact composition is found with Brent's method on that difference:


        
        
diagram_properties() then evaluates, at each point, the activity coefficients, K-values and fugacities. Fugacities are computed from the liquid side and from the vapor side; they agree, which is the equilibrium condition itself.


        
3D surfaces

        
The 3D view needs no new thermodynamics. web_api.surface() runs the same diagram at a list of values of the fixed variable and returns them as layers; the page joins equal liquid compositions across layers into a surface:



        
Other calculations in the same module

        

          
P–T diagram
pt_envelope() holds the composition and steps through temperature, solving a bubble and a dew pressure at each. Each guess is extrapolated from the last two points, using the fact that \(\ln P\) is nearly linear in \(1/T\).

          
Flash
flash_TP() fixes \(T\) and \(P\) and solves the Rachford–Rice equation for the vapor fraction, for any number of compounds.

          
Solid–liquid
One equation, liquid fugacity equals solid fugacity, solved for temperature or composition; the eutectic is where two such curves meet.

        


        
External fields

        
In a gravity or centrifugal field the equilibrium condition becomes \(\ln\hat f_i + M_i\Phi/RT = \text{constant}\) along the system. The potential per unit mass:


        
column_profile() marches along height or radius. At each position it solves for the pressure and composition that put every compound's fugacity on its target:


        
and switches phase where the fluid reaches saturation. The calculator's field panel uses exactly this: build_input() writes the field, the system's extent and the state at the reference position (the bottom, or the inner radius) into the input, a flash at that state gives the phase there, and column_profile() marches from it. On the activity route the liquid's pressure dependence needs its molar volume, which the database does not hold; web_api.rackett_VL() estimates it from \(T_c\), \(P_c\) and \(\omega\) with the Rackett equation, and the input file says so.

Running in the browser

        
The calculator runs the Python modules themselves, not a copy written in JavaScript. A background worker loads Pyodide (Python compiled to WebAssembly) and NumPy, fetches the module files from the site's py/ folder, and calls web_api.handle() with each request. Nothing is sent to a server.

        
Two things make this practical:

        
    
          
          
  • A small download. The two root finders the solver needs, Brent's method and a Newton solver for two unknowns, are written out in numerics.py, so the browser loads only Python and NumPy.
    • 
          
  • Surfaces computed in advance. A 3D surface is fifteen diagrams. Those with the database parameters are solved once by scripts/precompute_surfaces.py and loaded as files; others are computed in the browser once and remembered there.
    • 
          
  • Fast inner loops. The cubic is solved in closed form, and the mixing rules are evaluated once per fugacity call.
    • 
        

        
For use without an internet connection, run python scripts/dev_server.py and open http://localhost:8000/. The page detects the local server and sends its requests there, to the same web_api.handle() running in ordinary Python.

      


      
      

        
The compound database

        
data/compounds.json is generated by scripts/build_compound_db.py, so no value is typed by hand. The script reads the list of wanted compounds from data/compound_list.csv (name, formula, CAS number) and looks each one up by CAS number in published tables distributed with the open-source chemicals and thermo libraries. Every value is stored with a tag naming its source.

        
To add a compound, add one row to the CSV file and run the script again. The Reference page lists the compounds, the sources and the full citations.

Limitations and next steps

        
Limitations

        
    
          
  • On the activity route the vapor is an ideal gas, so that route is for low to moderate pressure.
    • 
          
  • The van Laar parameters vary with temperature only as \(a + b/T\), fitted between the two boiling points. Outside that range they are extrapolated, and the calculator says so. They are regressed from NRTL rather than directly from measurements.
    • 
          
  • Antoine constants are fitted over a limited temperature range. Outside it the vapor pressure is extrapolated, and the calculator says so.
    • 
          
  • Equations of state use van der Waals mixing rules with one \(k_{12}\). That suits hydrocarbons and is poor for polar mixtures.
    • 
          
  • Near a mixture critical point, bubble and dew calculations with an equation of state can fail. The curves stop there and a note is shown.
    • 
          
          
  • Diagrams are for two compounds. Flash and single bubble or dew points work for any number.
    • 
        

        
Next steps

        
    
          
  • Comparison with experimental data sets, with deviations reported and parameters fitted.
