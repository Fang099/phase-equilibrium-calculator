The pipeline

The program is a chain of Python modules. Each one takes the output of the one before, so each can be tested alone. The calculator page and the command line both feed the same chain.

  1. Input checkerinput_checker.py

    Reads a plain-text description of the mixture, converts units, fills in database values, and decides whether the information is sufficient and which calculation it implies.

  2. Thermodynamic modelsthermo_models.py

    Builds one object per phase. Each object answers one question: what is the fugacity of every compound at this \(T\), \(P\) and composition?

  3. Equilibrium solverequilibrium_solver.py

    Finds the states where fugacities match between phases, and sweeps them into diagrams and tables.

  4. Outputplotter.py · web_api.py

    Draws figures with Matplotlib from the command line, or returns numbers as JSON for the charts on the calculator page.

Supporting files: compound_db.py and data/compounds.json (the property database), and numerics.py (root finders used when SciPy is not availablethe root finders).

The rest of this page follows one request: ethanol and water, {{act}} model, a Txy diagram at 1.01325 bar.

2. The input checker

        
check_input(text) works through the file in five steps.

        
    
          
  1. Parse. Each line is a quantity, an optional target (a compound or a pair) and a value with a unit. Unknown names get a spelling suggestion.
    2. 
          
  2. Convert units to SI: kelvin, pascal, joule per mole, kilogram per mole.
    3. 
          
  3. Fill from the database. With database = builtin, any property the file does not give is looked up: \(T_c\), \(P_c\), \(\omega\), molar mass, Antoine constants, and the pair's NRTL parameters, van Laar parameters \(A_{ij}(T) = a_{ij} + b_{ij}/T\) or Peng–Robinson \(k_{12}\). Values written in the file always win.
    4. 
          
  4. Choose a route for each possible equilibrium. If an equation of state was requested and its constants are complete, it is used for both phases. Otherwise the checker looks for a vapor-pressure source for each compound and uses the activity model for the liquid.
    5. 
          
  5. Count degrees of freedom with the phase rule and compare with what was specified. Here \(F = 2 + 2 - 2 = 2\): the pressure is given and the composition is swept, so the problem is exactly specified.
    6. 
        

        
The verdict is one of four words. SUFFICIENT means it can be solved. INSUFFICIENT lists what is missing. OVERSPECIFIED says how many variables to remove. INVALID points at a mistake in the input. This is the actual report for the request above:

        

      


      
      

        
3. The fugacity models

        
build_system(text) creates two objects for this request: a liquid and a vapor. Every phase object has the same method, ln_f(T, P, x), which returns \(\ln \hat f_i\) for each compound. The solver never needs to know which model is behind it.

        

          

            
Phase objectUsed for\(\ln\hat f_i\)

            
              
SolutionLiquidLiquid with an activity model (or ideal)\(\ln x_i + \ln\gamma_i + \ln f_i^{L}\)

              
IdealGasPhaseVapor on the activity route\(\ln(y_i P)\)

              
EOSPhaseLiquid or vapor from a cubic equation of state\(\ln x_i + \ln\hat\varphi_i + \ln P\)

              
PureSolidPhaseA pure solid (command-line program)\(\ln f_i^{L} + \ln(f_i^{S}/f_i^{L})\)

            
          

        

        
Activity route (this example)

        
The pure-liquid fugacity \(f_i^{L}\) is the vapor pressure from the Antoine equation, multiplied by a Poynting correction \(\exp[V_i^{L}(P - P_i^{\mathrm{sat}})/RT]\) when a liquid volume is given. \(\ln\gamma_i\) comes from the NRTL class, which holds the model's \(G^{E}\) and its analytic derivatives. Margules and VanLaar have the same two methods, ge_rt and ln_gamma.\(\ln\gamma_i\) comes from the VanLaar class, which holds the model's \(G^{E}\) and its analytic derivative in two methods, ge_rt and ln_gamma. An ideal solution is the same with \(\ln\gamma_i = 0\). A van Laar parameter can be a number or a formula in \(T\), as in the input above; the formula is evaluated at the temperature of each point, so the activity coefficients change along a Txy diagram.

        
Equation-of-state route

        
CubicEOS stores van der Waals, SRK and Peng–Robinson as one residual Helmholtz energy with two constants:

        \[ \frac{A^{\mathrm{res}}}{NRT} = -\ln\!\left(1-\frac{b}{v}\right) - \frac{a}{bRT(\delta_1-\delta_2)}\,\ln\frac{v+\delta_1 b}{v+\delta_2 b} . \]
        
Pressure and \(\ln\hat\varphi_i\) are coded as its exact derivatives, and the tests compare them with numerical derivatives of this function. To evaluate at a given \(T\) and \(P\), the cubic for \(Z\) is solved in closed form (Cardano's formula, then two Newton steps to polish), and the smallest or largest root is taken for liquid or vapor.

      


      
      

        
4. The equilibrium solver

        
One bubble point

        
A Txy diagram is a row of bubble points. For one liquid composition \(\mathbf x\) at the given pressure, the unknowns are the temperature and the vapor composition. The solver works with K-values, \(K_i = y_i/x_i = \hat\varphi_i^{L}/\hat\varphi_i^{V}\), and a material balance for a feed \(\mathbf z\) of which a fraction \(\beta\) is vapor (the Rachford–Rice equation):

        \[ \sum_i \frac{z_i\,(K_i-1)}{1+\beta\,(K_i-1)} = 0 . \]
        
With \(\beta = 0\) this is a bubble point and with \(\beta = 1\) a dew point, so one routine, saturation(), does both:

        
    
          
  1. Guess the temperature from K-values that ignore composition (Wilson's correlation for an equation of state, the ideal-solution value otherwise).
    2. 
          
  2. At a trial temperature, compute the vapor composition from the current K-values, recompute the K-values from the two phase models, and repeat until they stop changing.
    3. 
          
  3. Evaluate the Rachford–Rice sum. Step outward from the guess until it changes sign, then close in with Brent's method.
    4. 
          
  4. For an equation of state, reject a result where liquid and vapor came out identical (the "trivial solution" near a critical point).
    5. 
        

        
The diagram

        
vle_diagram() repeats this across the composition range, each point starting from the previous answer. For the website, the points are spaced more closely near the pure compounds, where the curves are steepest. Each bubble point also gives one point of the dew curve, since the vapor it finds is a vapor at its dew point.

        
Afterwards two checks runone check runs on the result:

        
    
          
  • Azeotrope. If \(y_1 - x_1\) changes sign between two neighboring points, the exact composition where \(y_1 = x_1\) is found by Brent's method.
    • 
          
  • Liquid stability. The second derivative of the Gibbs energy is evaluated at every point. If it is negative anywhere, the model predicts two liquid layers. The solver then looks for two liquid compositions whose bubble points share the same vapor and the same temperature, refines them with a two-variable root finder, removes the unphysical points between them and inserts the three-phase line.
    • 
        

        
Everything else along the curve

        
diagram_properties() then evaluates, at each point, the K-values, relative volatility, activity coefficients, fugacities, fugacity coefficients, \(G^{E}/RT\), the Gibbs energy of mixing and the stability functionthe activity coefficients, K-values and fugacities. Fugacities are computed from the liquid side and from the vapor side; they agree, which is the equilibrium condition itself. This table is what "plot any variable against any other" draws from.

        
Other calculations in the same module

        

          
P–T diagram
pt_envelope() holds the composition and steps through temperature, solving a bubble and a dew pressure at each. Each guess is extrapolated from the last two points, using the fact that \(\ln P\) is nearly linear in \(1/T\).

          
Flash
flash_TP() fixes \(T\) and \(P\) and solves the Rachford–Rice equation for the vapor fraction, for any number of compounds.

          
Solid–liquid
One equation, liquid fugacity equals solid fugacity, solved for temperature or composition; the eutectic is where two such curves meet.

          
Fields
column_profile() marches along height or radius, solving \(\ln\hat f_i + M_i\Phi/RT = \text{constant}\) for pressure and composition at each position, and switches phase where the fluid reaches saturation.

Running in the browser

        
The calculator runs the Python modules themselves, not a copy written in JavaScript. A background worker loads Pyodide (Python compiled to WebAssembly) and NumPy, fetches the module files from the site's py/ folder, and calls web_api.handle() with each request. Nothing is sent to a server.

        
Two things make this practical:

        
    
          
  • No SciPy needed. The solver uses only two SciPy routines, brentq and fsolve. numerics.py has plain-Python versions of both, used automatically when SciPy is absent. SciPy would be by far the largest download, so the calculator starts sooner without it. The test suite passes with either.
    • 
          
  • A small download. The two root finders the solver needs, Brent's method and a Newton solver for two unknowns, are written out in numerics.py, so the browser loads only Python and NumPy.
    • 
          
  • Fast inner loops. The cubic is solved in closed form, and the mixing rules are evaluated once per fugacity call.
    • 
        

        
For use without an internet connection, run python scripts/dev_server.py and open http://localhost:8000/. The page detects the local server and sends its requests there, to the same web_api.handle() running in ordinary Python.

      


      
      

        
The compound database

        
data/compounds.json is generated by scripts/build_compound_db.py, so no value is typed by hand. The script reads the list of wanted compounds from data/compound_list.csv (name, formula, CAS number) and looks each one up by CAS number in published tables distributed with the open-source chemicals and thermo libraries. Every value is stored with a tag naming its source.

        
To add a compound, add one row to the CSV file and run the script again. The Reference page lists the compounds, the sources and the full citations.

Limitations and next steps

        
Limitations

        
    
          
  • On the activity route the vapor is an ideal gas, so that route is for low to moderate pressure.
    • 
          
  • Margules parameters are constants. van Laar parameters vary as \(a + b/T\), fitted between the two boiling points and regressed from NRTL rather than directly from measurements.The van Laar parameters vary with temperature only as \(a + b/T\), fitted between the two boiling points. Outside that range they are extrapolated, and the calculator says so. They are regressed from NRTL rather than directly from measurements.
    • 
          
  • Antoine constants are fitted over a limited temperature range. Outside it the vapor pressure is extrapolated, and the calculator says so.
    • 
          
  • Equations of state use van der Waals mixing rules with one \(k_{12}\). That suits hydrocarbons and is poor for polar mixtures.
    • 
          
  • Near a mixture critical point, bubble and dew calculations with an equation of state can fail. The curves stop there and a note is shown.
    • 
          
  • When a model predicts two liquids, the three-phase line is calculated but the liquid–liquid boundary away from it is not.
    • 
          
  • Diagrams are for two compounds. Flash and single bubble or dew points work for any number.
    •
